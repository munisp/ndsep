## Protocol (why these numbers are honest)

| Model | Protocol | Rationale |
|---|---|---|
| fraud_net | **Time-based holdout 80/20** — fresh model trained on 2024-01-01 → 2024-05-26, evaluated on the *future* window 2024-05-26 → 2024-06-28 (24,000 txns) | Random splits leak behavioural patterns across time and overstate fraud performance. |
| credit_net | **Stratified 5-fold CV**, fresh model per fold, pooled out-of-fold predictions (800 orgs) | Dataset is small and has no time axis; k-fold gives honest out-of-sample estimates. |
| gnn_net | **Stratified node holdout 80/20**, fresh model (160 org nodes evaluated) | Standard transductive node-classification evaluation. |

All models retrained from scratch inside the harness — no leakage from the
canonical weights' own train/test split. ROC-AUC reported with percentile
**bootstrap 95% CIs** (1,000 resamples). Precision floor for the
recall@floor operating point: **0.2** (fraud-triage realistic).

### Threshold analysis — recommended operating points

| Model | Max-F1 threshold | P / R / F1 | Recall @ precision ≥ 0.2 | Threshold |
|---|---|---|---|---|
| fraud_net | 0.99 | 0.986 / 0.784 / 0.873 | 0.898 recall | 0.82 |
| credit_net | 0.56 | 0.398 / 0.805 / 0.532 | 0.966 recall | 0.38 |
| gnn_net | 0.69 | 0.714 / 0.600 / 0.652 | 1.000 recall | 0.08 |

At the fraud base rate of ~0.3%, the default 0.5 threshold is meaningless
(precision 0.12, F1 0.22). **Recommended production operating point for
fraud triage: threshold 0.82** (recall ~90%, precision ~20% — about 4 false
alarms per true fraud, which a review queue can absorb) or **0.99** for a
high-precision alerting mode (precision ~99%, recall ~78%).

### Calibration

- fraud_net is reasonably calibrated (ECE 0.081); scores can be read as
  rough probabilities after the 0.82 threshold mapping.
- credit_net is **poorly calibrated** (ECE 0.342): class-weighted training
  inflates raw scores (observed default rate in the top bins is far below
  the mean predicted). Use it as a *ranking* score, or fit an isotonic/
  Platt calibrator on out-of-fold predictions before exposing raw
  probabilities. Ranking quality (AUC 0.853) is unaffected.
- gnn_net is acceptable (ECE 0.139) but the small test set (160 nodes)
  makes the calibration curve noisy; CI is correspondingly wide.

Full reliability bins are in `validation_results.json`
(`models.<m>.calibration.bins`).

## ⚠ Honest status: "validated against real fraud cases" is NOT yet achieved

Everything above is measured on **synthetic** labels (documented generator,
`ml/data/generate_synthetic.py`). It proves the *pipeline* is correct and
the models learn the injected typologies — it does **not** prove production
performance. Claiming "validated against real fraud cases" requires from
NDPC / partner institutions:

1. **A data-sharing agreement** (NDPA-compliant) covering labeled fraud
   cases from regulated institutions.
2. **Labeled case data** in the schema documented in
   `ml/validation/real_case_ingest.py` (CSV/parquet: tx_id, timestamp,
   amount_naira, channel, sender_org, receiver_org, is_fraud, + optional
   fields). The ingest path is built and tested: unmappable rows are
   quarantined, valid rows land in the lakehouse as `real_cases`, and
   `fine_tune.py` automatically up-weights them (3×) in training batches.
3. Re-run of this harness against the merged dataset; the time-based
   holdout then measures real-world generalization.

The harness is ready; **real labels are pending**.
